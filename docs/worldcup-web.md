# 世界杯赔率展示页 · 设计文档（Web + H5）

> 状态：设计稿，待评审。遵循项目「文档先行 → 方案确认 → 开发」工作流。

## 1. 产品定位

一个**实时世界杯赔率看板**，让用户在一个页面里：

1. **总览**所有比赛（对阵、时间、核心赔率）一眼扫完；
2. **下钻**单场，看全部 5 种玩法的完整赔率；
3. **辅助决策**——每场给出返还率、去水概率与「价值提示」，帮用户理解
   赔率背后的含义，而非盲目下注。

**它不是什么**：不是投注平台、不替用户下注、不承诺盈利。定位是「赔率
信息的可视化与解读工具」。

### 目标用户场景

- 「今天有哪几场，哪场值得看 / 赔率有意思？」→ 列表页扫一眼。
- 「这场具体什么盘口？平局赔率多少？」→ 详情页看全。
- 「为什么说这场是均势盘？」→ 价值分析区解释。

## 2. 数据来源与技术架构（三阶段管线）

页面**不实时联网**。数据在构建期生成、运行期纯展示。原因：真正有价值的
分析（球队判断、价值解读）是 AI 推理，前端 JS 算不出来；改为离线生成后，
页面退化为纯 JSON 渲染器——零接口依赖、零 CORS、加载快。

```
阶段①  爬虫取数 + 数学分析    tools/build_wc_data.py
        拉区间内所有 mid 的赔率，算好 A 类指标(返还率/去水概率/标签)
        产出  →  data/worldcup.json   (机器/脚本，可重跑)

阶段②  AI 分析(点评+购买方案)  我(对话中完成)
        读 worldcup.json，逐场写 commentary，存回
        产出  →  data/worldcup.json   (人/AI，重跑爬虫时按 mid 保留)

阶段③  静态渲染               worldcup.html + css + js
        读 data/worldcup.json，纯展示，不计算、不联网
```

**两类分析的分工（关键认知）**：

- **A 类·数学分析**：返还率、去水概率、价值标签——赔率的纯函数，确定性，
  由阶段①脚本算好写入 `metrics`/`tags`。
- **B 类·AI 判断**：「平局被低估」「客胜不贵」「20元购买方案」——超出赔率
  之外的推理，由阶段②人工(我)写入 `commentary`。

接口（仅阶段①脚本使用，页面不碰）：

- `getMatchHeadV1.qry?source=web&sportteryMatchId=<mid>` —— 对阵信息
- `getFixedBonusV1.qry?clientCode=3001&matchId=<mid>` —— 全部赔率
- 队徽图片接口直接返回（`homeTeamLogoPath`），96×96 PNG，已验证可用。

**重要约束 · 数据是冻结快照**：赔率与点评都停在爬取/分析那一刻，页面不会
自更新。顶部须显著标注「数据截止 crawledAt / 分析时间 analyzedAt」。

**重要约束 · 重跑保留点评**：阶段①重跑时，odds/metrics/tags 更新覆盖，
但 commentary **按 mid 保留**不弄丢。注意：保留 ≠ 自动更新——赔率变了，
点评需重新让 AI 分析才能跟上。

**mid 区间**：固定默认 `[2040162, 2040176]`，仅由维护者在脚本参数中配置，
不做成页面输入。

## 4. 价值分析的设计（核心差异点）

把专业数字「翻译」成普通人能懂的提示，**信息分三层**：

**第一层 · 价值标签**（卡片上就能看到，一眼定性）

| 标签 | 触发条件（基于去水概率） | 含义 |
|------|------------------------|------|
| 🔥 大热盘 | 某方去水概率 ≥ 60% | 一边倒，赢了赔得少 |
| ⚖️ 均势盘 | 三项概率最大差 ≤ 12% | 势均力敌，赔率都体面 |
| 💎 关注平局 | 平局去水概率 ≥ 30% | 易平，平局可能有价值 |
| 🧊 小球倾向 | 总进球众数 ≤ 2 | 进球不多 |

**第二层 · 可视化**（详情页，色块/进度条）

- 三色概率条：主胜/平/客胜 去水概率，按宽度直观对比。
- 返还率徽章：88.6% 绿 / 79.7% 黄 / 71.0% 红，提示该玩法「抽水」高低。

**第三层 · 原始数据**（详情页可折叠）

- 隐含概率和、各玩法返还率、盈亏平衡胜率等，给想深究的人。

## 7. 视觉规范（沿用项目调性）

- 复用 otakumap 的动态渐变背景 + 玻璃拟态卡片 + 深色系。
- 字体：Inter（数字/拉丁）。赔率数字用等宽或 tabular-nums，保证对齐。
- 主色语义化：
  - 赔率高低用色温——低赔(热门)偏暖红，高赔(冷门)偏冷蓝。
  - 返还率徽章：绿(>85%) / 黄(78~85%) / 红(<75%)。
- 卡片 hover：轻微上浮 + 边框高亮（沿用 otakumap）。

## 8. 交互与状态

| 状态 | 处理 |
|------|------|
| 加载中 | 骨架屏（复用 otakumap 风格），按预估场次数占位 |
| 某场未开盘 | 卡片显示「未开盘」，灰显，仍可点看已开玩法 |
| 接口失败 | 该场卡片单独显示错误 + 重试，不连累整页 |
| 全部失败 | 整页错误态 + 重试按钮 |
| 空区间 | 「该区间无比赛」空状态 |

- 刷新：手动按钮 +（可选）每 N 分钟自动刷新，带「最后更新」时间戳。
- 详情：Web 滑出面板（Esc / 点遮罩关闭）；H5 整页切换（返回键/手势）。

## 10. 合规与风险（必须正视）

- **内容性质**：涉博彩赔率，公开部署有合规风险（国内语境）。
- **建议**：
  - 页面显著位置标注「数据来自中国体育彩票官网，仅供参考，不构成投注建议」；
  - 强调竞彩负和本质（返还率 < 100%，长期期望为负）；
  - 评估是否将仓库转私有，或该页不纳入公开导航。
- **接口礼貌**：并发拉取需限流（如并发 ≤ 5 + 间隔），避免被封 IP。
- **免责声明**组件化，列表页底部 + 详情页均出现。

## 13. 赛程总览日历（schedule）

随着赛事推进、赔率列表变长，找某天比赛成本变高。顶部新增**赛程总览日历**，
覆盖整届 104 场，点击某天平滑滚动到列表对应日期分组。

### 13.1 数据来源与隔离

- 由 `tools/build_schedule.py` 从 ESPN 区间接口拉整届赛程，转北京时间，
  按天聚合，写入 `data/worldcup.json` 的顶层 `schedule` 字段。
- **与赔率严格隔离**：本脚本只写 `schedule`，绝不碰 `matches`（赔率/点评/战绩）。
  刷新赔率用 build_wc_data.py，刷新赛程用 build_schedule.py，互不污染。
- 阶段字段用 ESPN 的 `season.slug`（可靠），非 name 关键词（实测与 slug 矛盾）。
- ESPN 单次区间约 100 场上限，脚本分两段查询按 event id 去重，确保 104 场全。

### 13.2 schedule 数据契约

```jsonc
"schedule": {
  "source": "ESPN site.api（赛程总览，非赔率）",
  "fetchedAt": "2026-...",
  "totalMatches": 104,
  "days": [{
    "date": "2026-06-12", "md": "6/12", "weekday": "周五",
    "total": 2,                          // 当天场次
    "phases": {"小组赛": 2},             // 各阶段计数
    "mainPhase": "小组赛", "phaseOrder": 1, // 主阶段(场次最多)，序号供排序
    "groupRound": 1                      // 小组赛轮次(1/2/3)，淘汰赛为 null
  }]
}
```

阶段映射（slug→中文）：小组赛/32强/16强/8强/4强/季军赛/决赛。

**小组赛轮次（groupRound）**：小组赛72场按时间序每24场一轮（48队12组、每轮24场、
共3轮）。轮次在日期上不重叠（R1:6/12-18 / R2:6/19-24 / R3:6/25-28），故可按天归属。
脚本据此给每个小组赛日标 1/2/3，淘汰赛日为 null。

### 13.3 前端日历（js/worldcup/calendar.js）

- 两版视觉，`state.calView` 切换：`strip`(横向日期条) / `grid`(月历网格)。
- **响应式默认**：Web(>768px)默认月历、移动端(≤768px)默认日期条；跨断点
  自动切默认，用户手动切后尊重选择（`calViewByUser` 标记，不再被 resize 覆盖）。
- 点击某天 `scrollToDay()` 平滑滚到 `#day-YYYY-MM-DD` 并金色高亮闪烁。
  列表日期分组带锚点 id（render.js），与日历 data-date 对应。
- 无赔率列表的天（赔率未开）灰显，点击抖动反馈"未开放"。
- **当日属性**：日历格子显示场次数 + 轮次/阶段短标（R1/R2/R3/32/16/8/4/季/决）；
  列表日期分组头加阶段标签徽章（`buildDayMeta`）+ 场次数。
- **今天标识**：按浏览器实时日期 `new Date()`（非冻结数据）高亮当天，日历格子
  金色描边+脉冲、日期条带"今天"角标，列表分组头加"今天"徽章。世界杯结束后
  当天不在赛程内则不高亮，无副作用。

### 13.4 阶段/轮次配色规范

小组赛与淘汰赛用**两个色系**拉开区分：

| 阶段 | class | 色 |
|------|-------|-----|
| 小组赛R1 | `.gr-1` | 浅蓝 |
| 小组赛R2 | `.gr-2` | 中蓝 |
| 小组赛R3 | `.gr-3` | 深蓝 |
| 32强 | `.ph-2` | 青绿 |
| 16强→决赛 | `.ph-3`~`.ph-7` | 黄绿→黄→橙→紫→金（随晋级升温） |

- 小组赛三轮统一蓝色系、深浅分轮次；淘汰赛暖色系。两段一眼可分。
- 取色函数 `dayColorClass(d)`：小组赛看 `groupRound` 取 `gr-*`，淘汰赛看
  `mainPhase` 取 `ph-*`。`dayShortLabel`/`dayPhaseName` 同理区分。

> 两版日历并存（Web默认月历/H5默认日期条）；列表去掉"按小组"，固定按日期。
