# 世界杯赔率页数据更新

触发此 skill 时，**你（Claude）要在当前对话里完整走一遍数据更新流程**。
这不是一个静默后台脚本——爬取是机器做的，但 AI 点评必须由你逐场撰写。

## 背景认知（必读，避免做错）

- 项目是 GitHub Pages 静态站，页面 `worldcup.html` 只读 `data/worldcup.json`。
- **html / css / js 永远不用改**——数据变了，用户刷新浏览器即最新。
  绝不要去"更新 html"，那是错误认知。
- 数据是**冻结快照**：赔率和点评都停在本次更新时刻。
- 两类分析分工：
  - A 类（返还率/去水概率/标签）：`build_wc_data.py` 自动算，你不用碰。
  - B 类（点评 summary/value + 购买方案 plan）：**你写**，这是本 skill 的核心工作。

## 执行步骤

### 第 1 步：确定 mid 区间

- 用户传了两个数字（如 `/worldcup 2040200 2040220`）→ 用该区间。
- 没传 → 用默认区间 `2040162 2040176`。

### 第 2 步：跑爬虫，刷新赔率与数学指标

```bash
cd <项目根>
python3 tools/build_wc_data.py <起始mid> <结束mid>
```

- 该脚本会拉取最新赔率、重算 A 类指标、**并按 mid 保留已有 commentary**。
- 但本 skill 要求**重写全部点评**，所以旧 commentary 会被你下一步覆盖。
- 留意输出里的场次列表和 status（open / hhad_only / 未开盘）。

### 第 3 步：读取数据，逐场撰写点评（核心）

读 `data/worldcup.json`，对**每一场** open 或 hhad_only 的比赛，基于其真实
赔率重写 commentary。撰写规范见下方「点评撰写规范」。

### 第 4 步：写回 JSON 并校验

- 把点评写回每场的 `commentary` 字段。
- 更新 `meta.analyzedAt` 为当前时间。
- **校验每个 plan 的 stake 之和 == budget（20）**，不符必须修正。

### 第 5 步：报告完成

告诉用户：更新了几场、mid 区间、数据截止时间，并提示**刷新浏览器**查看
（如本地预览需 `python3 -m http.server` 起服务后开 worldcup.html）。

## 点评撰写规范

每场 commentary 结构（与数据契约一致）：

```jsonc
"commentary": {
  "summary": "一句话定性，点出盘型与核心信号",
  "value":   "价值判断：用盈亏平衡胜率 vs 去水概率说理，指出哪个选项被高/低估",
  "plan": {
    "budget": 20,
    "bets": [ {"market":"...","odds":数字,"stake":投入,"potential":中回} ],
    "note": "方案逻辑一句话"
  }
}
```

### 分析方法论（基于赔率，不是凭空猜）

1. **盈亏平衡胜率 = 1/赔率**。与该选项的去水概率比较：
   - 直接买的赔率算出的平衡胜率 > 去水概率 → 偏贵，负期望，不推荐直接买。
   - 反之 → 相对有价值。
2. **强队大热场**（某方去水≥60%）：直接买主胜通常偏贵。**但让球不是万能解药**——
   见下方「让球红线」。让球方向（赢得透 vs 赢不透）在实力悬殊/淘汰赛场几乎无法预判，
   32强复盘让球 ROI -32%、两方向都错。有明确方向理据才用，否则转小比分或不碰。
3. **客强主弱/大热客队**（客胜赔率很低如<1.5）：推**受让方的让胜**替代追客胜——
   同样受「让球红线」约束，弱队受让不败在淘汰赛常落空（32强让+1让胜全灭）。
4. **均势盘**（三项概率极差≤12%）：突出平局或次热项的价值；让球方向此时更难判，慎用。
5. **hhad_only**（无胜平负，仅让球/比分）：只能玩比分，覆盖热门比分区间，
   **必须注明"比分返还率约71%最重，纯娱乐"**。

### 让球红线（两轮复盘血泪，硬约束）

> 依据：[docs/round-of-32-review.md](../../docs/round-of-32-review.md)、[docs/round1-review.md](../../docs/round1-review.md)。
> 小组赛让球看似+48%(幸存者偏差)，32强直接崩到-32%，是最大失血玩法。

- **不再"每场无脑让球打底"**。让球只在**能写清方向理据**时用（实力差+本届淘汰赛表现+战意），
  理据写进 value，不能只是"惯例"。
- **强弱悬殊场**：让负(赌赢不透)碰碾压必输、碰主队恰好赢1球也判平输；让胜+1(受让不败)
  淘汰赛弱队常扛不住。两头都是陷阱——**这类场宁可不碰让球**，玩小比分或平局。
- **让球若用，也不再默认占大头**（32强主菜多为让球，主菜ROI -27%）。方向没把握就降额或分散。

### 购买方案规则

- 预算固定 20 元；`bets` 的 stake 之和必须 == 20。
- `potential` = round(odds × stake, 2)，写时算准。
- 通常 2-3 注组合。**主菜不必执着于让球**——只有方向有把握时才押大头；
  方向靠猜（多数淘汰赛让球场）就分散或降额，别把大注压在掷硬币的玩法上
  （32强主菜 ROI -27%，教训见「让球红线」）。
- **比分最多 1 注，且只押小比分**（1:0/1:1/0:1）。两轮比分 ROI 均约 -20%，
  返还率最低(71%)、命中靠撞，别每场撒 1~2 注比分。
- 优先用返还率高的玩法（胜平负 88.6% > 总进球/半全场 79.7% > 比分 71%）。
- **不因单轮小样本正收益追捧某玩法**（如32强胜平负+43%仅3注、总进球+17%仅7注，是噪声非信号）。

### 风险底线（每场都要守）

- 点评是**主观判断，非赚钱承诺**。措辞避免"稳赢""必中"。
- plan 在页面上已自动配强免责声明，但 note/value 里也不得诱导加大投注。
- 竞彩是负和游戏，长期期望为负——这个基调贯穿所有点评。

## 实现提示

- 逐场写点评时，可仿照历史做法用一次性 Python 脚本批量写回（写完即删，
  不提交），或直接用编辑工具改 JSON。无论哪种，写回后务必校验预算。
- 不要提交临时脚本和 `__pycache__`。
- 数据更新后是否 git 提交，**等用户明确要求**，不主动 commit。
