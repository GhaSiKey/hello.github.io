# 世界杯模拟买盘 · 赛后结算

触发此 skill 时，**你（Claude）在对话里完成结算流程**：找出待结算的比赛、
搜索真实比分、与用户确认、调用判定工具写回。

与 `/worldcup` 的分工：
- `/worldcup` = 赛前：爬赔率 + 写 AI 点评（分析）。
- `/settle`   = 赛后：获取赛果 + 判定输赢（结算）。**本 skill 不碰赔率、不写点评。**

## 背景认知（必读）

- 结算工具 `tools/settle_results.py` 已封装好判定逻辑，**不联网**，按 mid 填
  比分、判定每注、重算 betSummary，**只动指定场，不重新爬取**。
- 判定规则与 `js/simbet/judge.js` 一致。半全场注**需要半场比分**，拿不到就
  标"无法结算"(hit=null)，不计盈亏——口径诚实，不要瞎填。
- **绝不要用 `build_wc_data.py` 来结算**——那是全量爬取覆盖的脚本，接口 403
  时会把数据清空。结算只用 `settle_results.py`。
- 取数工具 `tools/fetch_results.py` 从 **ESPN 公开接口**拉赛果，**只读不写**：
  自动识别"已开赛未结算"的场次、按队名三字码+主客方向贴回 mid、按 90 分钟
  常规时间折算比分（淘汰赛只取前两段，不含加时点球），输出可复制的 settle
  命令。它不碰 json，写入仍归 `settle_results.py`——取数与判定隔离。
- **比分主来源 = `fetch_results.py`（ESPN）**，WebSearch 降级为交叉验证兜底。
  体彩接口已 403 封禁不用；中文比分站多为博彩 SEO 垃圾，不可信，别依赖。
- ESPN 队名映射表在 `fetch_results.py` 顶部 `CN_TO_ESPN`，新增场次需补条目；
  匹配不上的场次脚本会明确标"队名未在映射表"，不静默跳过。

## 执行步骤

### 第 1 步：取数（跑 fetch_results.py）

直接跑取数脚本，它会自动找出"已开赛未结算"的场次并拉 ESPN 赛果：

```bash
python3 tools/fetch_results.py            # 扫所有待结算场次
python3 tools/fetch_results.py <mid>      # 只查指定场（用户指定时）
```

- 脚本输出每场的全场比分、半场比分、完赛状态，以及拼好的 settle 命令。
- 完赛(FT)的标 ✓；未完赛/未匹配的标 ⏳ 并说明原因（如"队名未在映射表"）。
- 若某队名未在映射表 `CN_TO_ESPN`，先补上映射再重跑，别跳过。

### 第 2 步：交叉验证比分（WebSearch 兜底）

ESPN 是权威来源，但比分写错会把整个战绩算歪，**关键场次仍要交叉验证**：
对每场用 WebSearch 搜一眼 `2026世界杯 <主队> <客队> 比分`，与 ESPN 对照。

- 重点核对：**比分方向**（主客别反）、**是否常规时间**（淘汰赛排除加时点球）。
- ESPN 与搜索结果不一致时，停下来查清楚，不要硬结算。
- 半场比分常只有 ESPN 有，搜不到属正常；搜不到不代表 ESPN 的错。

### 第 3 步：列清单给用户确认（关键，防错）

把取到并交叉验证过的比分**汇总成一张表**，一次性给用户确认：

```
待结算 N 场，ESPN 取到比分如下（已交叉验证），请核对：
  墨西哥 vs 南非    全场 2:0   半场 1:0
  韩国   vs 捷克    全场 2:1   半场 0:0
  ...
确认无误我就结算，有错请指正。
```

**必须等用户确认或修正后再结算**，不要取完直接写入。比分错了会把整个
战绩算错，宁可多问一句。

### 第 4 步：逐场结算

用户确认后，直接执行 `fetch_results.py` 输出的 settle 命令；或手动调用：

```bash
python3 tools/settle_results.py <mid> <主进球> <客进球> [半场主 半场客]
```

- 有半场比分就带上（能结算半全场注）；没有就只传全场两个数。
- 脚本会判定每注、算本场盈亏、重算全局 betSummary 并写回。

### 第 5 步：报告战绩

汇总本次结算结果：各场比分与盈亏、AI 命中情况、当前总战绩
（已结算 X/15、命中率、总盈亏、ROI），提示用户刷新 simbet.html 查看。

## 边界与防错

- **比分方向**：settle_results.py 的参数是 `<主进球> <客进球>`，务必按
  data 里的 home/away 顺序传，别搞反。搜索时也按"主队 客队"核对。
- **半场比分缺失**：只传全场两个参数即可，半全场注会自动标"无法结算"，
  不影响其它玩法判定。事后若补到半场比分，可重新结算该场覆盖。
- **重复结算**：对已 finished 的场再次结算会覆盖，是幂等的，安全。
- **加时/点球**：竞彩玩法按**90分钟常规时间**结果判定（不含加时点球）。
  搜比分时取常规时间比分；淘汰赛尤其注意区分。
- **数据保护**：settle 只改指定场，不会清空数据。但仍建议结算前后用
  `git status` 看改动，异常随时 `git checkout data/worldcup.json` 回滚。

## 不做的事

- 不提交 git（除非用户明确要求）。
- 不修改赔率、不重写点评（那是 /worldcup 的职责）。
- 不在比分未经用户确认时写入结算结果。
