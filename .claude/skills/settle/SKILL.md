# 世界杯模拟买盘 · 赛后结算

触发此 skill 时，**你（Claude）在对话里完成结算流程**：找出待结算的比赛、
搜索真实比分、与用户确认、调用判定工具写回。

与 `/worldcup` 的分工：
- `/worldcup` = 赛前：爬赔率 + 写 AI 点评（分析）。
- `/settle`   = 赛后：获取赛果 + 判定输赢（结算）。**本 skill 不碰赔率、不写点评。**

## 背景认知（必读）

- 结算工具 `tools/settle_results.py` 已封装好判定逻辑，**不联网**，按 mid 填
  比分、判定每注、重算 betSummary，**只动指定场，不重新爬取**。
- 判定规则与 `js/simbet/judge.js` 一致。半全场注**需要半场比分**，拿不到就
  标"无法结算"(hit=null)，不计盈亏——口径诚实，不要瞎填。
- **绝不要用 `build_wc_data.py` 来结算**——那是全量爬取覆盖的脚本，接口 403
  时会把数据清空。结算只用 `settle_results.py`。
- 体彩接口当前可能 403（反爬封禁），所以比分**走 WebSearch**，不依赖接口。

## 执行步骤

### 第 1 步：找出待结算的比赛

读 `data/worldcup.json`，筛出 `result.status != "finished"` 且开赛时间
（`datetime`）已过的场次。列出它们的 mid / 对阵 / 开赛时间。

- 若用户指定了某场（传 mid 或队名），只结算那场。
- 否则批量处理所有"已开赛但未结算"的场次。

### 第 2 步：搜索比分

对每场用 WebSearch 搜真实比分，查询形如
`2026世界杯 <主队> <客队> 比分 全场 半场`。

- **优先找到全场比分 + 半场比分**（半全场注需要半场）。
- 搜索要点：注意确认是 2026 世界杯该场、比分方向（主客别搞反）。
- 半场比分常搜不到——搜不到就标记该场"半场未知"，不要编造。

### 第 3 步：列清单给用户确认（关键，防搜错）

把搜到的比分**汇总成一张表**，一次性给用户确认：

```
待结算 N 场，搜到比分如下，请核对：
  墨西哥 vs 南非    全场 2:0   半场 1:0
  韩国   vs 捷克    全场 1:1   半场 未搜到
  ...
确认无误我就结算，有错请指正。
```

**必须等用户确认或修正后再结算**，不要搜完直接写入。比分错了会把整个
战绩算错，宁可多问一句。

### 第 4 步：逐场结算

对每场已确认的比分，调用：

```bash
python3 tools/settle_results.py <mid> <主进球> <客进球> [半场主 半场客]
```

- 有半场比分就带上（能结算半全场注）；没有就只传全场两个数。
- 脚本会判定每注、算本场盈亏、重算全局 betSummary 并写回。

### 第 5 步：报告战绩

汇总本次结算结果：各场比分与盈亏、AI 命中情况、当前总战绩
（已结算 X/15、命中率、总盈亏、ROI），提示用户刷新 simbet.html 查看。

## 边界与防错

- **比分方向**：settle_results.py 的参数是 `<主进球> <客进球>`，务必按
  data 里的 home/away 顺序传，别搞反。搜索时也按"主队 客队"核对。
- **半场比分缺失**：只传全场两个参数即可，半全场注会自动标"无法结算"，
  不影响其它玩法判定。事后若补到半场比分，可重新结算该场覆盖。
- **重复结算**：对已 finished 的场再次结算会覆盖，是幂等的，安全。
- **加时/点球**：竞彩玩法按**90分钟常规时间**结果判定（不含加时点球）。
  搜比分时取常规时间比分；淘汰赛尤其注意区分。
- **数据保护**：settle 只改指定场，不会清空数据。但仍建议结算前后用
  `git status` 看改动，异常随时 `git checkout data/worldcup.json` 回滚。

## 不做的事

- 不提交 git（除非用户明确要求）。
- 不修改赔率、不重写点评（那是 /worldcup 的职责）。
- 不在比分未经用户确认时写入结算结果。
